# SM70 MXFP4 MoE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a TurboMind-backed SM70 MXFP4 MoE backend for GPT-OSS inference.

**Architecture:** Reuse the existing SM70 FP8 direct MoE Python flow and the TurboMind GEMM plumbing already compiled for SM70 AWQ/FP8. Add MXFP4-specific prepare and batched GEMM ops using TurboMind `kFloat4_e2m1` converters and E8M0 scale bytes.

**Tech Stack:** Python, PyTorch custom ops, CUDA C++, TurboMind GEMM, vLLM FusedMoE.

---

## File Structure

- Modify `vllm/model_executor/layers/fused_moe/oracle/mxfp4.py`: add `SM70_TURBOMIND` backend selection and kernel class mapping.
- Modify `vllm/model_executor/layers/quantization/mxfp4.py`: lower min capability to 70 and delegate SM70 direct method.
- Add `vllm/model_executor/layers/quantization/sm70_mxfp4_moe.py`: direct routed MoE method modeled on `Fp8SM70DirectMoEMethod`.
- Modify `csrc/ops.h`, `csrc/torch_bindings.cpp`, `vllm/_custom_ops.py`: expose MXFP4 prepare and GEMM ops.
- Modify `csrc/quantization/awq/awq_sm70_gemm.cu`: add MXFP4 prepare and batched GEMM implementations.
- Add or extend `tests/quantization/test_mxfp4_sm70.py`: focused backend and method tests.
